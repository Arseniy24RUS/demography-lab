# Семинар без интернета на Mac

Автономный комплект запускает на Mac общий сервер занятия и локальную базу PostgreSQL/PGlite. Телефоны и ноутбуки открывают платформу в браузере по адресу Mac внутри учебной Wi-Fi сети. Внешний интернет, Supabase, Docker и установка приложения на устройства слушателей во время занятия не нужны. Локальная сеть между устройствами и работающий Mac необходимы: отключение Wi-Fi от Mac нельзя заменить открытой ранее вкладкой.

В комплект входят собранный интерфейс, региональные программы с каноническим текстом и исходными документами, карты, статистические ряды, шрифты для экспорта, все миграции, движок базы и Node.js. Источники и их контрольные суммы сохраняются. Совместные действия выполняются через тот же предметный SQL-контракт; локальный транспорт заменяет облачный сервис. Поддерживаются документы и цитаты, семейства практик, голосования, барьеры, отдельная анкета, территориальные команды, дорожные карты, уточнения статистики и экспорт. Актуальность и сопоставимость статистики не меняются от способа запуска.

## Два способа подготовки

| Что скачано | Что делает Prepare.command | Нужен ли интернет для подготовки |
|---|---|---|
| Полный архив `Demography-Lab-…-Mac-universal.zip` | Автоматически выбирает Node.js для Apple Silicon или Intel, проверяет файлы, создаёт базу | Нет |
| Полный архив `Demography-Lab-…-Mac-arm64.zip` | Проверяет файлы и контрольные суммы, создаёт локальную базу из включённого корпуса | Нет |
| Полный архив `Demography-Lab-…-Mac-x64.zip` | То же; предназначен для Mac с процессором Intel | Нет |
| Исходный проект GitHub или архив исходного кода | При необходимости скачивает зафиксированный официальный Node.js; выполняет `npm ci`, кэширует оригиналы документов, собирает интерфейс и создаёт базу | Да, выполнить заранее |

Универсальный комплект содержит обе сборки Node.js и автоматически выбирает подходящую. `arm64` соответствует Mac с Apple Silicon, `x64` — Intel. Архитектуру можно посмотреть в меню Apple → «Об этом Mac». В полный Mac-комплект включён официальный Node.js 24.22.2; SHA-256 исходного архива зафиксирована в `scripts/macos/runtime-lock.json`. Зависимости PGlite и хеширования закреплены точными версиями. Обновление Node.js выполняется новым проверенным выпуском, без фонового скачивания во время занятия.

Распакуйте ZIP целиком в постоянную папку, например `~/Documents/DemographyLab`. Не запускайте отдельный файл внутри просмотра ZIP. Откройте папку `macos` и дважды нажмите `Prepare.command`. Подготовка переносит полный корпус в локальную базу и может занять несколько минут. Дождитесь сообщения о завершении. Прерванная подготовка не считается готовым семинаром: повторно запустите Prepare до занятия. Если macOS запрашивает разрешение открыть скачанный файл, подтвердите открытие конкретного проверенного файла штатными средствами системы. Скрипты не требуют `sudo`, не отключают защиту macOS и не меняют настройки Wi-Fi.

## Какая сеть нужна

Наиболее воспроизводимая конфигурация для выездного занятия — отдельный Wi-Fi роутер или точка доступа с DHCP, к которой подключены Mac и слушатели. Подключение WAN к интернету не требуется. Подключение Mac по Ethernet к этому роутеру обычно оставляет больше пропускной способности Wi-Fi для телефонов; подключение Mac по Wi-Fi также возможно. Выберите собственное имя сети и пароль, включите выдачу локальных адресов, отключите изоляцию клиентов (`AP isolation`, `Client isolation`, гостевую изоляцию). Конкретные названия настроек зависят от оборудования. Не используйте гостевую сеть, которая запрещает доступ к другим устройствам.

Второй вариант — функция macOS «Общий интернет» (`Internet Sharing`). В руководстве Apple для macOS 27 описана раздача с выбранного исходного интерфейса, например Ethernet, на Wi-Fi: «Системные настройки» → «Основные» → «Общий доступ» → «Общий интернет» → «Настроить». В поле источника выбирается отдельный интерфейс, а Wi-Fi — как способ подключения слушателей. Устанавливаются имя сети, совместимый режим WPA2/WPA3 или WPA3 и пароль. [Руководство Apple](https://support.apple.com/en-hk/guide/mac-help/mchlp1540/27/mac/27).

Это не означает, что Mac с единственным Wi-Fi адаптером гарантированно создаст независимую точку доступа без другого сетевого интерфейса. Руководство Apple описывает совместное использование существующего подключения; доступные интерфейсы, активный Ethernet и поведение при отсутствии внешнего канала надо проверить именно на вашем Mac. Платформа не создаёт фиктивный Ethernet, не заменяет системный драйвер и не перенастраивает NAT. Если «Общий интернет» не запускает сеть в выбранной аппаратной конфигурации, используйте подготовленный роутер без WAN. Это снимает зависимость занятия от особенностей одного Wi-Fi адаптера.

Откройте `Network.command`. Скрипт покажет доступные IPv4-адреса, адрес приложения и отдельный адрес анкеты. Он только читает настройки компьютера, не обращается в интернет. По вашему выбору открывается системный раздел общего доступа; переключатели остаются под вашим управлением. Если показано несколько интерфейсов, выберите адрес той сети, к которой подключены слушатели. VPN-интерфейсы помечаются отдельно. Адрес `127.0.0.1` предназначен только для преподавателя на самом Mac, его нельзя показывать слушателям как общий адрес.

## Запуск в аудитории

Подключите Mac к питанию и учебной сети, оставьте крышку открытой. Дважды нажмите `Start-Seminar.command`. Команда сначала проверит полный состав и SHA-256 файлов, затем наличие подготовленной базы; скачивания, `npm install` и обращений к облаку в этом сценарии нет. После запуска откроется локальная платформа преподавателя. В терминале появятся адреса для слушателей. Скрипт использует штатный `caffeinate` с предотвращением автоматического сна компьютера и гашения экрана во время работы сервера, чтобы проекция оставалась видимой. Это не отменяет принудительное выключение, закрытие крышки, отдельные настройки проектора и потерю питания.

На Mac преподавателя открывается `http://127.0.0.1:8787/#sessions=1`. Вход преподавателя доступен через локальный режим интерфейса. Секрет преподавателя не помещается в адрес страницы, QR-код или журнал. Участники используют, например, `http://192.168.1.20:8787/`, где `192.168.1.20` — фактический адрес Mac, показанный программой. При изменении DHCP-адреса старый QR-код перестаёт быть верным: обновите адрес до начала занятия. Фиксированная DHCP-аренда на роутере позволяет сохранить адрес между запусками.

Слушатель открывает ссылку или QR-код занятия, вводит любой свой email и ФИО в одной форме и нажимает «Войти». Адрес служит постоянным идентификатором учебных результатов; подтверждать почту, регистрироваться отдельно или сохранять личный ключ для входа не требуется. Тот же порядок действует в онлайн-версии. Если браузер сохранил действующую сессию, повторный ввод не нужен; после выхода или на другом устройстве используются тот же email и ФИО. Ввод email преподавателя в форме слушателя не предоставляет полномочия преподавателя.

Управление локальным занятием открывается преподавателем на самом Mac через адрес `127.0.0.1`. Служебная проверка доступа выполняется автоматически между браузером на Mac и локальным сервером. Участникам передаётся ссылка на занятие с сетевым адресом Mac; переносить служебные файлы, вводить операторские данные или вручную набирать код занятия для входа им не нужно.

Если macOS спросит о входящих подключениях Node.js, разрешите их для учебной сети. При необходимости проверьте «Системные настройки» → «Сеть» → «Брандмауэр» → «Параметры» и разрешение конкретного приложения. Отключать брандмауэр целиком не требуется. Apple указывает, что до ответа на запрос попытки входящего подключения блокируются. [Настройки брандмауэра](https://support.apple.com/en-gb/guide/mac-help/mh34041/mac). Доступ к локальной сети также управляется в «Конфиденциальность и безопасность» → «Локальная сеть». [Разрешения локальной сети](https://support.apple.com/en-ae/guide/mac-help/mchla4f49138/27/mac/27).

Локальная установка использует два origin: порт `8787` для занятия и порт `8788` для исследовательской анкеты. Оба должны быть достижимы с устройств слушателей. Порт является частью origin, поэтому транспорт анкеты отделён от учётной сессии приложения и не получает её токены. Анкета открывается по ссылке, созданной преподавателем для конкретного опроса, а не путём замены порта вручную. Само разделение origin не означает абсолютную анонимность: физический сервер и резервные копии находятся у преподавателя.

Локальное соединение по умолчанию использует HTTP внутри выделенной сети. Wi-Fi должен иметь пароль; направлять эти порты в публичный интернет или включать переадресацию WAN не требуется. Для институционального развёртывания с доверенными сертификатами TLS настраивается отдельно до занятия. Обычный GitHub Pages не запускает локальную базу и не является заменой сервера Mac.

## Почему страница не всегда открывается сама

Подключение к Wi-Fi и открытие веб-страницы — разные действия. Автоматическое окно входа зависит от поддержки captive portal точкой доступа, её сетевой конфигурации и решения операционной системы телефона. Одна страница на порту `8787` не создаёт captive portal. Стандартный режим этой платформы не перехватывает DNS, HTTPS или чужие сайты и не обещает принудительного открытия страницы.

Надёжный способ входа — подключение к учебной Wi-Fi сети, затем сканирование QR-кода платформы либо ввод короткого локального адреса. Если iPhone предлагает выбрать сеть с интернетом, оставьте текущую сеть, выбрав «Без интернета»/`Without Internet`. Apple отдельно описывает, что этот выбор сохраняет подключение к сети и отключает её автоматический вход. [Поведение captive Wi-Fi на iPhone/iPad](https://support.apple.com/en-us/102554). Аналогичный запрос «Использовать эту сеть» может появиться на других устройствах. Открывайте основное приложение в обычном Safari, Chrome или Firefox: системное мини-окно captive portal не заменяет полноценный браузер для экспорта файлов и сохранения сессии.

Если роутер специально поддерживает captive portal, его начальную страницу можно направить на локальный адрес платформы и проверить на целевых телефонах. Настройка делается на выбранном оборудовании. Платформа не требует порта 80 и привилегированного системного сервиса; по умолчанию использует непривилегированные порты `8787` и `8788`.

## Где сохраняются результаты

По умолчанию данные располагаются в `~/Library/Application Support/DemographyLab`. Каталог находится вне папки программы: обновление исходного проекта или распаковка нового выпуска не должны удалять результаты. База, локальный профиль преподавателя, сведения о подготовке, технические журналы и резервные копии принадлежат этому экземпляру. Нельзя одновременно запускать два сервера с одним каталогом базы; сервер использует блокировку.

Email и ФИО используются для добровольной идентификации слушателя. Владение почтовым ящиком не проверяется ни при локальном, ни при онлайн-входе; участникам следует указывать собственный адрес и сохранять его написание при повторном входе. Совпадающий email позволяет продолжить работу под тем же учебным профилем в пределах выбранного экземпляра платформы. Локальные и облачные занятия остаются в разных базах: совпадение email не переносит между ними результаты автоматически. Итоговые материалы передаются явным экспортом.

Исследовательская анкета работает отдельно от учебного профиля. Её личный ключ нужен только для возвращения к собственному ответу и его отзыва; он не является ключом входа в платформу. Email и ФИО из учебной формы не передаются в анкету. Подробное разделение учебных результатов и исследовательских ответов описано в документации опроса.

Не закрывайте вкладку сразу после ввода последнего изменения: дождитесь подтверждения сохранения интерфейсом. Отображение текста на экране без подтверждения сервера не является сохранением в общей базе. При обрыве Wi-Fi восстановите подключение к той же сети и проверьте состояние операции; конфликты общей редакции разрешаются через интерфейс.

## Завершение, резервная копия, восстановление

После занятия откройте `Stop-Seminar.command`. Контроллер проверяет идентичность работающего экземпляра, запрашивает локальную резервную копию, затем штатное закрытие базы. Он не использует `killall`, не завершает посторонний Node.js и не доверяет одному номеру PID. Если создание резервной копии не подтверждено, сервер не останавливается автоматически: устраните причину, например нехватку места, и повторите команду. При успешной остановке данные остаются на диске.

`Backup.command` создаёт дополнительную копию во время работы либо обращается к остановленной базе в эксклюзивном режиме. Скопируйте завершённую резервную копию вместе с её manifest на другой накопитель. Копия на том же диске защищает от части ошибок приложения, но не от поломки самого диска. Резервная копия содержит персональные результаты и локальные секреты доступа; её нельзя публиковать в GitHub или раздавать как комплект программы. Распространяемый Mac-архив содержит только исходные данные и программный код, без вашей базы.

Восстановление выполняется при остановленном сервере в новый пустой каталог. Пример для стандартного установленного комплекта, где `node` — включённый runtime:

```bash
DW_OFFLINE_DATA_DIR="$HOME/Library/Application Support/DemographyLab-Restored" \
  ./runtime/darwin-arm64/bin/node scripts/offline/server.mjs \
  --restore "/absolute/path/to/backup-manifest.json"
```

Путь к manifest берётся из результата резервного копирования. В примере выбран универсальный комплект на Apple Silicon; для Intel путь — `runtime/darwin-x64/bin/node`, в комплекте одной архитектуры — `runtime/node/bin/node`. Восстановление проверяет контрольную сумму и не должно молча заменять существующую базу. Для следующего запуска укажите тот же `DW_OFFLINE_DATA_DIR`. Не объединяйте вручную файлы двух баз и не копируйте каталог работающего PostgreSQL обычным Finder вместо штатной резервной копии.

## Обновление с выпуска 0.7 на 0.8

В прежнем комплекте завершите работу командой `Stop-Seminar.command`: она сначала создаст резервную копию, затем закроет базу. Сохраните эту копию на отдельном накопителе. Распакуйте новый комплект в отдельную папку, чтобы программные файлы двух выпусков не смешались. Каталог `~/Library/Application Support/DemographyLab` остаётся прежним; если ранее задан собственный `DW_OFFLINE_DATA_DIR`, используйте тот же путь и в новом выпуске.

Запустите `Prepare.command` из нового комплекта и дождитесь завершения. Подготовка применит переход к входу по email и ФИО к существующей базе. Старый маркер готовности не требует ручного удаления; исторические SQL-миграции и сохранённые учебные данные не переписываются. Затем откройте новый `Start-Seminar.command`, проверьте прежнее занятие и повторный вход слушателя с тем же email. Для этого обновления полного Mac-комплекта интернет не нужен.

Новая идентификация сохраняет прежний идентификатор участника, найденный по нормализованному email. Если в базе старого выпуска уже существовали несколько разных профилей с одним адресом, для повторного входа выбирается наиболее ранний; их истории автоматически не объединяются и не удаляются. Не удаляйте базу для решения проблемы входа. При необходимости возврата к предыдущему выпуску используйте его резервную копию в отдельном каталоге восстановления, сохранив текущие данные.

## Параметры для технического специалиста

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `DW_OFFLINE_DATA_DIR` | `~/Library/Application Support/DemographyLab` на Mac | Общий каталог данных конкретного экземпляра |
| `DW_OFFLINE_PORT` | `8787` | Учебное приложение и локальный API |
| `DW_OFFLINE_SURVEY_PORT` | `8788` | Отдельный origin исследовательской анкеты |
| `DW_OFFLINE_HOST` | `0.0.0.0` | Прослушивание IPv4-интерфейсов; `127.0.0.1` ограничивает доступ самим Mac |
| `DW_OFFLINE_PUBLIC_HOST` | Определяется сервером из проверенного адреса запроса | Явный LAN IPv4/допустимое имя, если это требуется сетевой конфигурацией |

Сетевой инвентарь в машинном формате получается командой `node scripts/macos/network.mjs --json`. Она не отправляет сведения во внешние сервисы. Проверка целостности комплекта: `node scripts/macos/manifest.mjs check`. Штатная первичная подготовка базы: `node scripts/offline/server.mjs --prepare`. Работа без скачиваний: `node scripts/macos/control.mjs start`, остановка: `node scripts/macos/control.mjs stop`.

Сборщик автономного выпуска запускается после обычной сборки интерфейса и проверки корпуса. Он скачивает только официальный архив Node.js выбранной архитектуры, проверяет закреплённую SHA-256, включает локальные зависимости, весь `public/data`, шрифты, миграции и исполняемые `.command`, затем проверяет ZIP. Пример:

```bash
node scripts/macos/package-macos.mjs \
  --arch universal \
```

Для воспроизводимой сборки без повторной загрузки можно передать `--node-archive-arm64 /path/node-v24.22.2-darwin-arm64.tar.gz` и `--node-archive-x64 /path/node-v24.22.2-darwin-x64.tar.gz`; проверка суммы остаётся обязательной. При сборке одной архитектуры действует параметр `--node-archive`. В архив не включаются операторские ключи, действующая база и зависимости разработки. Нативные бинарные расширения не нужны: PostgreSQL в PGlite работает через WebAssembly.

## Что должна подтвердить очная репетиция

Перед реальным занятием следует проверить конкретный Mac, выбранный роутер/Internet Sharing и несколько устройств слушателей: подключение без WAN, открытие обоих портов, создание и изменение общего материала с двух устройств, повторный вход после перезапуска сервера, открытие оригинального документа, экспорт PDF/DOCX и создание резервной копии. На этом этапе также выбирается подходящий размер группы для фактического оборудования. Тесты кода в Linux не подтверждают системные разрешения macOS, радиопокрытие, пропускную способность точки доступа, Safari на конкретном iPhone или поведение captive portal. В этой разработке физическое испытание macOS 27 и Wi-Fi оборудования не выполнялось; программный комплект подготовлен для такой репетиции.
