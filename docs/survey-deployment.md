# Размещение формы опроса

## Вход в мастерской 0.9

Первый раздел общей мастерской — «Опрос». Любой вошедший участник получает два открытых вопроса и кнопку «Ответить анонимно». Форма создаётся и становится доступной автоматически; преподаватель не должен создавать кампанию, открывать приём или раздавать приглашения. Кнопка «К барьерам» позволяет продолжить обсуждение без заполнения анкеты.

Учебный сайт: <https://arseniy24rus.github.io/demography-lab/>. Форма: <https://demography-lab-survey.sunnydew4.chatgpt.site/survey.html>. Общая кнопка самостоятельно подставляет идентификатор анкеты и общий ключ формы. Участники не вводят и не копируют коды.

`dw_workshop_survey(p_session_id)` доступен текущим участникам единой мастерской. Он атомарно получает существующую форму или создаёт новую с двумя вопросами, контактом организатора `omnistat@yandex.ru` и сроком хранения 365 дней. Конкретная дата показана участнику до согласия на участие. Никакие ответы при этом не создаются. Вступление, чтение формы и участие в анкете не назначают преподавательские полномочия. Функция сохраняет закрытое состояние и сроки уже существующей анкеты, не переписывает её ответы и не продлевает ранее согласованный срок. Если приём ответов закрыт или срок истёк, начальный экран показывает этот статус и дату; переход к барьерам и остальная совместная работа остаются доступны.

На общей странице доступны только вопросы и число полученных ответов от пяти. Точные малые числа и личные тексты там отсутствуют. Преподаватель явно раскрывает «Ответы и обобщения» и запрашивает просмотр. Перенос на коллективную доску выполняется через сформулированное человеком обобщение. Исследовательская выгрузка учитывает самостоятельные согласия на исследование и цитирование.

## Разделение формы и учебного профиля

`index.html` обслуживает мастерскую с идентификацией по заявленному email. Независимый `survey.html` не импортирует account Auth SDK. Кнопка открывает форму на другом origin в новой вкладке с `noopener noreferrer` и `Referrer-Policy: no-referrer`. Отдельная вкладка также позволяет избежать ограничений браузеров на хранилище стороннего iframe.

Публичный транспорт `SurveyApi` отправляет только publishable key и поля анкеты: `credentials: omit`, `referrerPolicy: no-referrer`, без bearer учебного профиля. Сервер дополнительно отвергает пользовательский JWT. Общий ключ формы находится в fragment URL; персональный ключ ответа никогда не включается в URL. Общий ключ открывает только анкету, он не позволяет читать или удалять чужие ответы.

Ответы не имеют внешнего ключа к учебным профилям, email или акторам. Личный случайный ключ создаётся независимо до первой отправки и сохраняется только на origin анкеты. Тексты и согласия в браузерное хранилище не записываются. Ключ и операции опроса не входят в именной журнал активности или проектор. Публичный счётчик обновляется с интервалом около 30 секунд; отдельного события на каждый ответ нет.

В разделе «Управление моим ответом» участник может удалить свой ответ или сохранить текстовую памятку `.txt` для восстановления на другом устройстве. Файл не требуется для обычной отправки. Отзыв остаётся доступным после закрытия формы и истечения срока. Сервер сохраняет пустую запись об отзыве, чтобы повтор старой команды не восстановил текст.

Таблицы формы физически находятся в общем проекте PostgreSQL, инфраструктурные журналы обслуживаются отдельно. Процедура не гарантирует абсолютной невозможности установить автора по узнаваемому содержанию текста. Форма просит не указывать имена и личные подробности. Участие добровольное; можно отвечать о профессиональном опыте и пропускать вопросы.

## Публичная конфигурация

На обоих origin размещается `workshop-config.json` с одинаковыми адресами API и формы. Пример с вымышленными адресами:

```json
{
  "schemaVersion": 1,
  "supabaseUrl": "https://PROJECT.supabase.co",
  "supabasePublishableKey": "sb_publishable_REPLACE_WITH_PROJECT_PUBLIC_KEY",
  "identification": "declared-email",
  "realtime": false,
  "surveyUrl": "https://survey.example.org/survey.html",
  "classroomOrigin": "https://class.example.org"
}
```

`supabaseUrl` и `classroomOrigin` содержат origin без пути. `surveyUrl` завершается `/survey.html`. В конфигурации запрещены пароли, query и fragment. Учебный сайт и форма имеют разные origin. Рабочая онлайн-форма использует HTTPS. Автономный сервер на Mac автоматически публикует форму на другом порту того же доступного устройства; HTTP в этом режиме разрешён для локальной сети. Неверная конфигурация анкеты не блокирует остальные разделы мастерской.

`service_role`, секретные ключи и строка подключения PostgreSQL не включаются в клиентскую сборку, ZIP или HTML. Схемы `private` и `research` закрыты для прямого PostgREST. Новая таблица `private.dw_workshop_survey_access` содержит общий ключ формы и защищена RLS без прямых клиентских разрешений; доступ идёт через проверяющую членство RPC.

## Сборка и обновление отдельного сайта

`npm run build` создаёт обе точки входа. `npm run check:survey-bundle` проверяет полный граф JavaScript анкеты на отсутствие account-кода. После сборки используйте существующий checkout отдельного сайта с его `.openai/hosting.json`:

```sh
node scripts/deploy/package-survey-site.mjs \
  /absolute/path/to/existing-survey-site \
  https://demography-lab-survey.sunnydew4.chatgpt.site \
  https://arseniy24rus.github.io
```

Упаковщик переносит только HTML анкеты, используемые ресурсы, favicon, публичную конфигурацию и лицензии в `dist` отдельного сайта. Корпус программ и учебный вход туда не копируются. Изменения сохраняются в Git этого сайта, затем публикуется новая версия существующего Site с сохранением его текущего доступа. Публикация GitHub Pages самостоятельно отдельный Site не обновляет.

Идентификатор действующего отдельного Site: `appgprj_6af19af3694c81918393a30ef96050bb`. Конфигурация размещения — `.openai/hosting.json`, `static.directory: dist`. База API остаётся `alyrowehwzypgtrqnvdi`; новый Supabase-проект не требуется.

В чистой установке применяются все миграции по порядку. Обновление 0.9 добавляет `20261109163142_stage9_shared_workspace.sql`, затем `20261109163351_stage9_shared_workshop_survey.sql`. Исторические миграции не редактируются. Текущий общий ключ формы доступен только через metadata RPC, ответы — через существующие отдельные анонимные или преподавательские методы.

## Проверка

Требуются действительный переход из первого раздела общей мастерской, отправка через нативный браузерный fetch на отдельном origin, перезагрузка с восстановлением своего ответа, текстовая памятка и отзыв. В сетевых запросах формы проверяются отсутствие account Authorization, cookies и referrer. Общее чтение и проектор не должны содержать raw answers или личный ключ.

Тест `tests/offline/shared-survey.e2e.mjs` использует собранный клиент и настоящий автономный сервер, два независимых браузерных контекста и отдельный порт анкеты. Локальная проверка не заменяет проверку опубликованного отдельного Site, Safari, физических телефонов и сети аудитории.
