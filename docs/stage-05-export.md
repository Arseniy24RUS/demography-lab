# Экспорт зафиксированной дорожной карты

Модуль `roadmap-export-1` создаёт DOCX, PDF, JSON и ZIP из одной сохранённой версии `RoadmapVersion`. Во время построения файлов он не перечитывает живую комнату и не подменяет сохранённые материалы новыми редакциями. PDF и DOCX сохраняют размер A4 исходного шаблона организаторов: `11906 × 16838` twips. Основные расчёты выполняет общий пакет `roadmap-analytics-1`.

## Проверка перед построением файла

`prepareRoadmapExport` сначала выполняет строгую проверку DTO, разбирает `canonicalJson` и проверяет его соответствие `snapshot`. Затем SHA-256 вычисляется по точным UTF-8 байтам строки `canonicalJson`. Повторная сериализация с другим порядком полей или отступами не используется вместо этой строки.

Проверяются уникальные идентификаторы записей, источников, оснований и документальных снимков, единственность активных паспорта, диагноза и мониторинга, совпадение уровня территории. Для каждой закреплённой связи с региональным семейством требуется полное доказательное основание с теми же идентификатором и fingerprint. Статистический факт из реестра сверяется с сохранённым рядом по территории, идентификатору, fingerprint, году, значению, показателю и единице. Число, введённое вручную, сохраняет статус внешнего непроверенного факта.

Смета повторно рассчитывается по активным строкам с целочисленной арифметикой копеек и сравнивается с серверным финансовым итогом версии. Несовпадение контрольной суммы, статистического факта или финансового итога блокирует экспорт. Незаполненные поля, непроверенные полномочия, ожидаемое финансирование, устаревшие основания и ошибки воспроизведения сценария остаются видимыми замечаниями внутри документа; черновик можно выгрузить вместе с ними.

Результат подготовки является отдельной глубоко замороженной копией. Правка текущей комнаты или изменение исходного объекта после подготовки не изменяет уже подготовленный документ. SHA-256 подтверждает совпадение данных с полученным снимком, но не является электронной подписью, проверкой действующего права или подтверждением научной достоверности источников. Рецензия преподавателя хранится отдельно от канонического снимка и в эту выгрузку не подмешивается.

## Публичный интерфейс

| Точка входа | Контракт |
| --- | --- |
| `prepareRoadmapExport(version)` | Проверяет и замораживает данные; возвращает единый документный план и расчёты |
| `buildRoadmapDocx(prepared, { rasterizeSvg })` | Возвращает `Promise<Uint8Array>`; обработчик растеризации готовит PNG из внутреннего SVG |
| `buildRoadmapPdf(prepared, fonts)` | Возвращает `Promise<Uint8Array>`; шрифты и лицензия передаются явно |
| `roadmapJson(prepared)` | Возвращает полную JSON-строку с exact `canonicalJson`, структурированным снимком и расчётами |
| `buildRoadmapArchive(prepared, { rasterizeSvg, fonts })` | Возвращает ZIP из одного подготовленного снимка |
| `exportRoadmapVersion(version, format)` | Браузерный адаптер возвращает `{ blob, filename, mimeType }` |
| `downloadRoadmapVersion(version, format, canDownload?)` | Явное скачивание с повторной проверкой контекста перед выдачей файла |

Браузерный адаптер находится в `apps/web/src/lib/roadmap-export.ts`. Его следует импортировать динамически по действию пользователя. PDF, DOCX и ZIP загружаются отдельными динамическими импортами; JSON не требует библиотек рендеринга. Шрифты загружаются только при подготовке PDF или ZIP и только с origin самой платформы. Тексты дорожной карты не передаются внешним конвертерам.

`canDownload` вызывается до подготовки и после всех асинхронных расчётов. Компонент передаёт функцию, учитывающую его актуальное подключение, аккаунт и занятие. При выходе из аккаунта или смене контекста файл из старой комнаты не выдаётся. Созданный object URL отзывается через 60 секунд; эта задержка сохраняет совместимость с обработкой скачивания в Safari, но не означает отдельной проверки Safari в текущем протоколе.

## Содержательная структура

| Раздел результата | Содержание исходного шаблона и дополнения |
| --- | --- |
| 1 Паспорт проекта | Название, уровень, территория, адресаты, партнёры, цель, задачи, период, ожидаемый результат и защита |
| 2 Исходная ситуация | Проблема, причинная гипотеза, вывод, факты с годами и единицами, происхождение данных и основания выбора решений |
| 3 Показатели и сценарии | Определения показателей, числители и знаменатели, исходные величины, годовые цели, источники, ограничения, траектории и полные таблицы расчёта |
| 4 План мероприятий | Задачи, адресаты, масштаб, исполнители, продукты и критерии выполнения, связи с показателями, полномочия и требуемые решения |
| 5 Этапы и календарь | Этапы, периоды и результаты, диаграмма сроков, точные даты, длительности и зависимости |
| 6 Ресурсы и финансирование | Кадровые, материальные и информационные ресурсы; смета, основания цен, подтверждённые и ожидаемые средства, два финансовых разрыва и неденежный вклад |
| 7 Риски | Содержание риска, предупреждение, ответственный, признак наступления и резервное действие |
| 8 Мониторинг | Метод, периодичность, ответственный, промежуточный и итоговый отчёты, качественные результаты и устойчивость |

Приложение проверки комплектности расшифровывает 31 структурную позицию и сохраняет все замечания. Процент заполнения не назван научной, юридической или финансовой экспертизой.

Приложение документальных оснований сохраняет барьеры и их жизненные этапы, авторские решения, мотивировки переноса, статусы и ревизии. Для регионального семейства печатаются все варианты, получатели, размеры и условия, оригинальные источники и контрольные суммы, точные цитаты, контекст, идентификаторы блоков и диапазоны Unicode code points. Проверенное значение поля показывается отдельно от текущего содержания карточки. Номер страницы не выдумывается, если его нет в сохранённом контракте. Архивные основания отмечены явно; варианты из разных регионов не соединяются в одну условную меру.

Приложение источников включает географическую редакцию, исходные коды, статистические ряды со всеми закреплёнными годами и пропусками, имена файлов, коммиты и SHA-256. Архивные записи присутствуют в самостоятельном приложении и в JSON, однако не участвуют в действующем бюджете, сценариях и комплектности.

## Графики и расчётные ограничения

Сценарный график разделяет исходные значения, базовую и целевую траектории. Пропуск обрывает линию исходного ряда; нуль остаётся числом. Вертикальная граница показывает последнюю доступную точку именно выбранного показателя. Расчётный период имеет отдельный фон; линии различаются цветом, штрихом и маркерами. Полная таблица значений позволяет прочитать график без опоры на цвет.

Фактический базовый год, выбранное окно истории и годы оценки тренда приводятся раздельно. Ограничение прогнозного значения допустимой областью, неполные первичные метаданные и непроверенная сопоставимость территориальных границ не скрываются. Разность траекторий называется плановым разрывом. Она не объявляется причинным эффектом мероприятий или числом дополнительных рождений вследствие программы. Сумма разниц рассчитывается только для потоков; для состояния, коэффициента и доли она отсутствует.

Если сохранённые цели показателя отличаются от связанного сценария, появляется `TARGETS_DIFFER_FROM_SCENARIO`. Экспорт не перезаписывает цели и не блокирует осознанный выбор иной плановой величины. Основание расхождения должна пояснить команда.

Календарь строится по сохранённым датам, по десять строк на рисунок, с полной таблицей рядом. Начало и окончание включаются в длительность. Даты зависимых мероприятий автоматически не переносятся. При отсутствии периода паспорта шкала ограничивается известными датами мероприятий, и это сопровождается отдельным замечанием.

## Особенности форматов

DOCX содержит нативные редактируемые абзацы, заголовки и таблицы. У таблиц определены ширины колонок, светлые границы, отступы, повторяемая шапка и чередование фона. Строки с большим объёмом текста могут переходить на следующую страницу. Рисунки имеют SVG-представление и полноценный PNG fallback, поэтому не требуют поддержки SVG конкретным текстовым редактором. Номер версии и сокращённый SHA-256 присутствуют в колонтитуле; полная сумма включена в текст и свойства документа.

PDF формируется непосредственно из того же документного плана. Кириллица остаётся выделяемым и извлекаемым текстом. Графики рисуются векторами, а не снимками HTML. Встроены локальные DejaVu Sans и DejaVu Sans Bold; лицензия поставляется в `public/fonts/LICENSE-DejaVu.txt` и прикладывается к PDF. Точное содержимое `canonical.json` также вложено в PDF. Встроенные карты `ToUnicode` позволяют извлекать кириллицу.

Формат PDF/A и полная семантическая разметка PDF/UA в этом модуле не реализованы. Поддержка символов ограничена встроенным шрифтом: при отсутствии глифа экспорт выдаёт явную ошибку с кодом Unicode, сохраняя оригинальный текст без подстановки. DOCX и JSON доступны независимо. Автоматическая замена неподдержанных знаков в цитате не выполняется.

JSON включает точный `canonicalJson`, структурированный снимок, детальные расчёты, исходные наблюдения и замечания. Сырые исследовательские ответы не входят в контракт снимка; неожиданные поля отклоняются строгой схемой.

ZIP содержит `roadmap.docx`, `roadmap.pdf`, `roadmap.json`, точный `canonical.json`, рисунки SVG, лицензию, инструкцию и `manifest.json`. Для каждого содержательного файла в манифесте указаны число байтов и SHA-256. `SHA256SUMS.txt` дополнительно включает сумму самого манифеста и может проверяться стандартной командой `sha256sum -c SHA256SUMS.txt`. Контрольная сумма списка не замыкается на него самого. Форматирование `canonical.json` перед проверкой изменит его сумму.

## Проверка реализации

Изолированная регрессия экспортов и аналитики проходит командами `npx tsc --noEmit` и `npx vitest run tests/unit/roadmap-export.test.ts tests/unit/roadmap-export-browser.test.ts packages/analytics`. Проверяется 48 сценариев: 37 аналитических и 11 экспортных. Среди экспортных проверок есть подмена байтов снимка, расхождение его структурированных полей, неверный финансовый итог, искажённый статистический факт, отсутствие доказательного материала, посторонние поля, сохранность разных региональных условий и архива, встроенные шрифты PDF, точность вложенного JSON, все суммы ZIP и отмена скачивания после смены пользовательского контекста.

Полный синтетический образец для визуального контроля содержит все восемь разделов, сценарий с пропущенным последним годом, календарь, смету, подтверждённые и ожидаемые средства, разные региональные варианты, цитаты и архив. Значения примера не являются данными муниципалитета или действующими мерами. В нём специально сохранены финансовый разрыв и содержательные замечания для проверки их видимого экспорта. Реальный DOCX отрендерен через LibreOffice, реальный PDF — через Poppler: по 17 страниц A4, все страницы просмотрены. Кириллица извлекается, оба региональных варианта и архив присутствуют, точные байты вложенного `canonical.json` совпадают со снимком; текст PDF за границы листа не выходит. QA-файлы находятся вне поставляемого проекта, в `research/stage5-export-qa`; протокол — `QA-REPORT.md`, машинные результаты — `verification.json`, окончательные PNG — `docx-release` и `pdf-release`.

Проверка файлов в LibreOffice и локальном браузере не удостоверяет работу всех версий Microsoft Word, мобильных ОС и браузеров. Производственная проверка пользовательских устройств проводится отдельно. Экспорт не подтверждает размещённый Supabase, SMTP, Realtime или юридическую актуальность исходных мер.
