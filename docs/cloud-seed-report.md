## Источник и воспроизводимость

Источник зафиксирован публичным Git-коммитом [`ce65b09d4e800061948e9037e71f15410be42d90`](https://github.com/Arseniy24RUS/demography-lab/tree/ce65b09d4e800061948e9037e71f15410be42d90/public/data). Импортёр запрашивал файлы только с этого неизменяемого адреса. SHA-256 индекса корпуса: `86c6bf55df05a03931246cc4a092f31b66fd0a3d73d24e53de4923e626f0fd95`. SHA-256 территориального индекса: `02eaef7003e77fe059a94a6a6f9dd8edeff841e0d697f77579a91ce30c9148fa`.

Для корпуса применён тот же чистый валидатор канонических документов, что используется в `scripts/seed-supabase.mjs`. Для территорий и рядов применены контракты `scripts/seed-roadmaps.mjs` и `packages/territories/series.mjs`. Проверяются версии, метаданные, полный текст, порядок и типы блоков, страницы, контрольные суммы территориальных файлов и отпечатки статистических рядов. Существующие записи сравниваются с источником; несовпадение останавливает соответствующую транзакцию. Закрытие набора разрешено только при точном совпадении ожидаемых количеств и отпечатков.

Скрипты `scripts/deploy/edge-owner-seed.ts`, `build-edge-owner-seed.mjs`, `invoke-owner-seed.mjs` и `run-owner-seed.mjs` оставлены для воспроизводимости. Это ограниченный импортёр конкретного выпуска, а не универсальный административный SQL-интерфейс. Для нового выпуска потребуется явно проверить и обновить зафиксированные источники и ожидаемые количества. Текущий удалённый импортёр уже отключён; сохранённые команды не могут повторно импортировать данные без нового согласованного развёртывания.

## Защита временного импорта и его закрытие

Временная Edge Function `dw-owner-seed` использовала отдельный случайный операторский ключ длиной 32 байта. В функцию передавался только SHA-256 ключа; исходный ключ находился исключительно в закрытом временном файле за пределами репозитория. Проверка выполнялась до открытия соединения с базой. Были ограничены срок действия, размер запроса, HTTP-метод, тип содержимого и допустимые операции. Передать произвольный SQL, URL, таблицу или пользовательский набор данных через API было невозможно.

Соединение использовало штатный `SUPABASE_DB_URL`, доступный только серверной функции. Конфигурация `postgres` с `prepare: false` соответствует официальной [инструкции Supabase по подключению Edge Functions к PostgreSQL](https://supabase.com/docs/guides/functions/connect-to-postgres). Переменная описана среди [стандартных серверных секретов](https://supabase.com/docs/guides/functions/secrets). Операции импорта содержали только фиксированный DML для канонических таблиц. Миграции схемы через функцию не выполнялись; таблицы аккаунтов, результаты работы слушателей и исследовательские ответы не читались и не изменялись.

После завершения загрузки функция заменена версией **4** из `scripts/deploy/edge-owner-seed-disabled.ts`. Эта версия всегда возвращает `404 Not found` и не содержит импортов библиотек, чтения секретов, соединения с БД или операций изменения данных. SHA-256 развёрнутого артефакта по ответу Supabase: `5863f9416e4bcb42b556964a472404efa45ed5e6ad0c40115737d5deb2f6f7fb`.

В 10:14:59 UTC выполнены реальные HTTP-запросы к опубликованной функции: запрос без ключа и запрос с прежним действовавшим ключом оба вернули `404 Not found`. После этой проверки локальный файл одноразового ключа удалён. Проверка пяти файлов импорта и отключения не обнаружила исходного ключа, DDL или обращений к таблицам пользовательских данных. В шаблоне остаются только заполнители операторского хеша и срока действия.

## Проверка настоящего REST-интерфейса

Проверки выполнены через опубликованный `/rest/v1/rpc` проекта с публичным ключом приложения, без пользовательской сессии. В отчёте и исходном коде публичный ключ не дублируется.

| Вызов | HTTP | Ответ и значение проверки |
| --- | ---: | --- |
| `dw_bootstrap` | 401 | `42501`: анонимный вызов рабочего кабинета запрещён |
| `dw_roadmap_statistics_series` | 401 | `42501`: анонимный доступ к статистике сессии запрещён |
| `dw_survey_public_manifest` с заведомо отсутствующим приглашением | 400 | `SURVEY_INVITATION_INVALID`: запрос дошёл до функции проверки приглашения и был отклонён |

Эти проверки подтверждают доступность REST-маршрутов и перечисленные ограничения доступа. Они не подтверждают доставку одноразовых кодов почтой, работу внешнего SMTP, вход реального слушателя, подписки Realtime или завершённость всех облачных миграций. Готовность этих компонентов нельзя выводить только из успешного импорта. Машиночитаемое подтверждение количества данных, HTTP-результатов и закрытия импортёра находится в `cloud-seed-report.json`.
