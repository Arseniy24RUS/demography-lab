# Архитектура этапа 2

## Граница модуля

Версия 0.2 добавляет именную совместную работу к локальному исследовательскому инструменту. Локальная тетрадь содержит черновики в IndexedDB. Публикация является явным действием: в сессию отправляется одна карточка, её точные основания и комментарий. Сервер использует сочетание занятия, автора и локального ключа для устойчивой связи публикаций.

## Связь карточки и документа

`SharedPracticeBundle` включает `practice`, `occurrences`, `sources`, публичный `note` и версию схемы. В пакет не копируются локальный профиль, пользовательские email, вся тетрадь, диагностические метки каталога или полный PDF. Перед отправкой клиент повторно загружает нужные редакции и выполняет доменную проверку якорей. Сервер независимо читает зарегистрированные канонические блоки и сравнивает точный текст, кодовые позиции, окружающий контекст, порядок блоков, регион практики, документ, редакцию, нормализацию и SHA-256.

Позиции считаются в кодовых точках Unicode. JavaScript учитывает разницу с UTF-16 через доменный адаптер; PostgreSQL использует символьные позиции. Переход между несколькими блоками не превращается в один вымышленный непрерывный фрагмент. После загрузки редакция запечатывается; изменение или дописывание блоков запрещено триггером. Следующая редакция должна иметь новый идентификатор и контрольные суммы.

Реквизиты источника в принятой публикации заменяются значениями серверного реестра. Пользователь не может предъявить посторонний заголовок или URL как каноническое происхождение цитаты. Связь конкретного поля сохраняет проверенное значение; изменение суммы, получателей или условий снимает проверку соответствующего поля в редакторе. Сервер отвергает устаревшее `reviewedValue` со статусом `verified`.

Точное совпадение текста удостоверяет воспроизводимость цитирования. Семантическое соответствие полю остаётся суждением автора; фактическая эффективность меры и действие нормы на дату занятия не выводятся из этого совпадения. Проектор и доска показывают текстовые основания для содержательной дискуссии.

## Доступ и преподавательские права

Supabase Auth подтверждает email одноразовым кодом. Серверные функции требуют существующего подтверждённого пользователя и отклоняют анонимные аккаунты. Первое сохранение ФИО создаёт профиль. Возможность создавать занятия назначается через приватный реестр `private.facilitators`; первый посетитель сайта не становится преподавателем автоматически. Пользовательские `user_metadata` не участвуют в авторизации.

Публичные таблицы защищены RLS; прямые INSERT/UPDATE/DELETE обычным пользователям не разрешены. Изменения проходят через проверяемые RPC. Функции с повышенными правами находятся в приватной схеме, используют фиксированный `search_path`, проверяют автора, членство, роль, состояние сессии и ожидаемую ревизию. Публичные обёртки не являются `SECURITY DEFINER`. Приватная схема не должна входить в список схем, открытых PostgREST.

| Роль | Возможности |
| --- | --- |
| Host | Создать занятие при назначенных правах, управлять этапами, приглашением и ролями, снимать/восстанавливать публикации, открывать проектор |
| Participant | Читать занятие, публиковать и редактировать собственные карточки при открытом приёме, снимать свои работы с показа |
| Observer | Читать доступные материалы занятия |

Автор не может восстановить снятую с показа публикацию обычной повторной отправкой. Преподаватель не переписывает чужую карточку под именем её автора. Отзыв членства закрывает последующие чтения и изменения этой сессии. Уже прочитанные данные невозможно отозвать из памяти пользователя или сохранённого снимка экрана.

## Одновременная работа

Каждая изменяемая запись имеет ревизию. Редактор запоминает её при открытии, сохраняя черновик отдельно от обновляющейся доски. Несовпадение ожидаемой ревизии приводит к `REVISION_CONFLICT`. Клиент получает новое состояние для сравнения; автоматической перезаписи нет.

Операция получает UUID. Сервер хранит связанный с подтверждённым автором отпечаток аргументов и результат. Повтор той же операции не создаёт ещё одну публикацию; повтор UUID с другими аргументами отклоняется. Для экономии места квитанция содержит компактный результат, а повторный ответ может включать более новое состояние той же сессии.

Изменение и запись уведомления выполняются в одной транзакции. Realtime передаёт короткое событие с идентификаторами и ревизией, без карточки, почты, ФИО или кода входа. Получив уведомление, клиент сверяет cursor и запрашивает согласованный снимок, если данные изменились. Запоздалый ответ с меньшим cursor не подменяет более свежие данные. `dw_session_cursor` также проверяет действующее членство, поэтому оптимизация не сохраняет доступ отозванного участника.

При живой подписке клиент дополнительно сверяется приблизительно раз в 30 секунд. При отсутствии Realtime используется интервал 8 секунд. Неизменившаяся доска не загружается повторно: передаётся скалярный cursor. Скрытая вкладка прекращает периодические запросы и сверяется при возвращении. В явно обозначенной тестовой среде интервал равен 1 секунде. Интерфейс различает соединение, живые обновления, периодическую сверку, ошибку и отсутствие сети.

## Проектор

`dw_projector_snapshot` доступен преподавателю и формирует отдельный ответ с разрешёнными полями: название, этап, состояние, количество слушателей, видимые публикации и выбранная работа. Он не содержит списка членов сессии, account email, UUID пользователей, локальных ключей или кода приглашения. Отображение авторского имени включается отдельно. Свободный текст самой работы автоматически не анонимизируется.

Адрес проектора содержит только идентификатор занятия и флаг режима; токены авторизации в URL не помещаются. Проектор использует учётную запись преподавателя в открывающем его браузере. Выбранная карточка сохраняется при появлении новых публикаций. Длинные цитаты делятся на видимые страницы с сохранением исходного текста.

## Объём и эксплуатация

Основной интерфейс, модуль Supabase, совместная доска и проектор загружаются отдельными частями. Публичный корпус обслуживается как статические ресурсы. В серверной базе хранится одна каноническая копия текста для проверки цитат; PDF не передаётся через Realtime. Ограничение публикации — 128 КиБ, суммарного объёма карточек сессии — 4 МиБ, числа участников — 1 000, публикаций — 5 000. Практический предел определяется первым достигнутым ограничением. Следующий рост требует пагинации снимков.

Выбор Supabase не означает отсутствие платы за исходящий трафик: [официальная документация учитывает egress и превышение квот](https://supabase.com/docs/guides/platform/manage-your-usage/egress). В этой версии реализованы короткие уведомления, сверка по cursor и загрузка текстов по необходимости; бюджет конкретного размещения определяется актуальным тарифом и использованием. Автоматическое создание платного ресурса в процесс сборки не входит.

## Проверка и первичные источники

SQL применяется к реальному PostgreSQL-движку PGlite с тестовой схемой Auth. Второй слой проверяет настоящий `@supabase/supabase-js` через локальный HTTP-сервер и ту же миграцию. Третий слой выполняет действия в независимых браузерных контекстах. Тестовая выдача OTP проверяет клиентский протокол, но не работу SMTP или размещённого Supabase Realtime. Эти проверки включены в процедуру подключения перед настоящим занятием.

[Supabase: passwordless email](https://supabase.com/docs/guides/auth/auth-email-passwordless), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Postgres Changes](https://supabase.com/docs/guides/realtime/postgres-changes), [database functions](https://supabase.com/docs/guides/database/functions), [API keys](https://supabase.com/docs/guides/api/api-keys). Контракт выпуска зафиксирован в `packages/collaboration/types.ts`, ограничения — в SQL-миграции и тестах.
