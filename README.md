# Демографическая мастерская · версия 0.8.2

Накопительный выпуск объединяет чтение региональных программ, совместную учебную работу, карту распределения источников, семейства практик и коллективное оценивание. Слушатель находит точные цитаты, проверяет поля карточки, публикует её в занятии и участвует в обсуждении. Преподаватель управляет этапами, группировкой региональных вариантов, раундами оценивания и показом результатов на проекторе. Четвёртый модуль добавляет жизненные барьеры, обоснованные связи с практиками, авторские решения и самостоятельную форму открытого опроса. Пятый модуль объединяет участников в территориальные команды с одной общей дорожной картой, исходной статистикой, сценариями, мероприятиями, календарём, сметой и неизменяемыми версиями для экспорта.

Личная работа вошедшего участника сохраняется на сервере: в Supabase онлайн либо в базе на Mac при автономном семинаре. Прежняя локальная тетрадь сохраняется отдельно и может быть добавлена в профиль через понятную кнопку. Модуль 2 добавляет учебные сессии, роли и общую доску. Выпуск 0.8 вводит одинаковую простую идентификацию онлайн и офлайн: участник сначала вводит только email. Существующий профиль открывается с сохранённым ФИО; если профиля ещё нет, имя запрашивается вторым шагом. Письма, OTP, отдельная регистрация, ручной код занятия и ключ восстановления не требуются. Для совместной работы используется локальный сервер на Mac либо Supabase-проект с миграциями и каноническим корпусом. Публичная онлайн-конфигурация указывает на проект владельца demography-lab. Начиная с 0.8.1 преподаватель использует общую форму: email `omnistat@yandex.ru`. Сохранённое имя подставляется из профиля. Модуль 3 добавляет карту 89 региональных паспортов, назначения с проверкой конкурирующих действий, сравнение и объединение практик с сохранением первоисточников, управляемые раунды и рейтинг. [Порядок подключения](supabase/README.md), [сценарий этапа 3](docs/runbook-stage-03.md) и [границы проверки](docs/stage-03-acceptance.md) входят в комплект. При обновлении с 0.3 применяется новая миграция этапа 4; прежняя история занятий сохраняется. [Сценарий этапа 4](docs/runbook-stage-04.md), [его архитектура](docs/architecture-stage-04.md) и [размещение отдельной анкеты](docs/survey-deployment.md) описаны отдельно.


## Вход и профиль в версии 0.8.2

Email служит заявленным идентификатором учебной работы. Повторный ввод того же адреса в пределах выбранного локального экземпляра или облачного проекта возвращает прежнюю идентичность и материалы, включая вход с другого устройства. ФИО сохраняется в профиле и подписывает публикации. Адрес не проверяется письмом; ограничения университетских доменов из RUDN не переносятся.

Ссылка преподавателя сразу определяет занятие. При обычном входе единственное открытое занятие открывается автоматически; при нескольких доступных занятиях участник выбирает нужное из списка. Преподаватель входит по той же ссылке и через то же поле email: нормализованный email `omnistat@yandex.ru` открывает управление занятиями онлайн и в локальной сети. ФИО, роль, «Изменить ФИО» и «Выйти» показаны в шапке на всех учебных экранах. Технический токен сессии сохраняется автоматически в браузере, никаких действий с ним от слушателя не требуется. Отдельная исследовательская анкета сохраняет независимый ключ отзыва ответа.

[Архитектура простого входа](docs/architecture-stage-08.md) и [приёмка выпуска](docs/stage-08-acceptance.md) описывают новую модель; старые протоколы этапов сохраняют историческую информацию.

## Модуль 0.7: общий семинар без интернета

Полный автономный сервер запускает совместную мастерскую на Mac и сохраняет общую базу на его диске. Слушатели работают с телефонов и ноутбуков через учебную Wi-Fi сеть. Документы и точные цитаты, совместные доски, назначения регионов, голосования, барьеры, отдельная анкета, территориальные команды, дорожные карты, ручная статистика и экспорт используют локальные API и тот же предметный SQL-контракт. Обращение к внешним сервисам во время такого занятия не требуется.

Для Mac предусмотрен универсальный ZIP с готовым интерфейсом, оригиналами документов, картами, статистикой, шрифтами, PGlite и официальными сборками Node.js для Apple Silicon и Intel. Сценарий запуска находится в папке `macos`:

| Файл | Действие |
|---|---|
| `Prepare.command` | Заранее проверяет комплект и создаёт полную локальную базу; в полном Mac-архиве работает без интернета |
| `Network.command` | Показывает локальные адреса, объясняет сетевое подключение и по выбору открывает настройки macOS |
| `Start-Seminar.command` | Проверяет готовность, запускает сервер без загрузок и открывает кабинет преподавателя |
| `Backup.command` | Создаёт дополнительную проверяемую резервную копию |
| `Stop-Seminar.command` | Запрашивает резервную копию и штатно закрывает локальную базу |

Данные сохраняются отдельно от программы, по умолчанию в `~/Library/Application Support/DemographyLab`. Преподаватель и слушатели входят с любого устройства учебной сети: сначала только email, ФИО — отдельным шагом при первом входе. Возврат к прежним материалам выполняется повторным вводом того же адреса. Перенос аккаунтов и результатов между локальным экземпляром и облаком автоматически не выполняется.

Для надёжной сети без внешнего интернета подходит отдельный Wi-Fi роутер с DHCP и отключённой изоляцией клиентов. Mac может раздавать Wi-Fi через штатный Internet Sharing при подходящей конфигурации исходного и раздающего интерфейсов; руководство Apple описывает, например, Ethernet → Wi-Fi. Программа не обещает автономную точку доступа на единственном Wi-Fi адаптере. Автоматическое открытие страницы на телефоне зависит от captive portal и ОС; рабочий способ подключения — два QR-кода: сеть и адрес мастерской. [Полная инструкция для macOS 27](docs/offline-macos.md) включает первичные источники Apple, сетевые разрешения, остановку и восстановление.

Приложение слушает порт `8787`, отдельная анкета — `8788`. Оба порта обслуживаются Mac; персональная анкета не получает учебный токен. Исходная база, подтверждённые результаты и резервные копии находятся у преподавателя, поэтому абсолютная анонимность не заявляется. Подготовку исходного GitHub-проекта выполняют с интернетом; полный Mac-комплект включает все необходимые файлы заранее. [Приёмка автономного режима](docs/stage-07-acceptance.md) отделяет проверки кода и сборки от очной репетиции на конкретном оборудовании.

## Модуль 0.6: актуализация статистики

В общей дорожной карте территории откройте «Диагностику» → «Уточнить данные». Команда может исправить любое значение всех семи исходных показателей, заполнить пропуски, добавить новые годы и создать ряд для территории без импортированной статистики. Редактор показывает исходный пакет и рабочую редакцию, принимает русский числовой ввод, различает ноль и отсутствие данных и требует источник с основанием изменения.

Уточнения сохраняются по годам: новый источник не присваивается всей предыдущей истории. Исходный импорт остаётся неизменяемым. Доступны журнал с автором и временем, просмотр прежних редакций, возврат отдельного года или целого ряда. Конкурирующее сохранение одного показателя обнаруживается по ревизии; открытый ввод сохраняется и повторно проверяется пользователем.

Сохранённые сценарии и факты используют закреплённую редакцию статистики. Для перехода к новой предусмотрено «Пересчитать по актуальным данным» и последующее сохранение. DOCX/PDF/JSON/ZIP сохраняют точные числа и происхождение из зафиксированной версии. Полнота и актуальность сведений команды не подтверждаются автоматически. [Порядок работы](docs/runbook-stage-06.md), [архитектура](docs/architecture-stage-06.md), [методика](docs/stage-06-data-method.md), [обновление БД](docs/stage-06-database.md) и [приёмка](docs/stage-06-acceptance.md) входят в комплект.

При обновлении заполненной версии 0.5 применяется новая миграция `20261109002211_stage6_team_statistics.sql`; четыре прежние миграции и исходный набор не изменены. Текущее состояние облачного подключения описывается отдельно от исторической приёмки этого модуля; см. текущий выпускной отчёт.

## Модуль 0.5: территориальные дорожные карты

Вкладка «Территории» открывает реальные муниципальные слои и диагностику без аккаунта. В занятии выберите «Дорожные карты»: участники одной территории присоединяются к одной общей карте. Работа проходит через территорию, диагностику, мероприятия, календарь и ресурсы, проверку и экспорт. Текстовые разделы и отдельные строки имеют независимые ревизии; конфликт одной записи показывает изменения команды и сохраняет открытый пользовательский вариант.

Источники — закреплённые редакции проектов [Settlements-projection-dashboard](https://github.com/Arseniy24RUS/Settlements-projection-dashboard/tree/59b778760c9efa6fe30d6ad17beec6ea622f30b5) и [RUDN](https://github.com/Arseniy24RUS/RUDN/tree/08c68f1fe1c812ed059b0b124b25c26c6fdd374f). В наборе 89 региональных слоёв, 2 381 территориальная единица, из которых 2 325 допускают муниципальную команду. Статистические ряды однозначно присоединены к 1 725 единицам; Мордовия — 23 из 23. Это авторский производный набор, а не удостоверенная полная актуальная выгрузка БДМО. Пропуски и известная аномалия Саранска показаны явно. [Паспорт данных](docs/data-stage-05.md) определяет состав и пределы использования.

DOCX, PDF, JSON и ZIP формируются из одной зафиксированной версии с проверкой SHA-256. Для практик сохраняются точные цитаты и исходные карточки; изменения обсуждения не подменяют прежние основания. Сценарный разрыв не считается доказанным эффектом мер. Заявки на финансирование не считаются подтверждёнными средствами. [Сценарий двух пар](docs/runbook-stage-05.md), [архитектура](docs/architecture-stage-05.md), [подключение сервера](docs/stage-05-database.md) и [приёмка](docs/stage-05-acceptance.md) входят в комплект.

Для обновления заполненной версии 0.4 примените только новую неприменённую миграцию `20261108225303_stage5_territorial_roadmaps.sql`, затем выполните импорт `scripts/seed-roadmaps.mjs` в выбранную среду. Прежние миграции и исследовательская анкета сохраняются. Для облачного размещения проверяйте фактический статус схемы, импорта и серверных функций по выпускному отчёту; наличие исходного SQL само по себе не подтверждает готовность выбранного проекта.

## Исходный репозиторий и готовый комплект

**Онлайн-публикация и вход проверены.** Владелец переключил GitHub Pages Source на GitHub Actions; повторная публикация завершилась 9 ноября 2026 года в **15:06:18 мск (UTC+3)**. Оба публичных адреса отдают собранный JavaScript. В живом браузере подтверждены форма из двух полей, повторный вход прежнего участника, сохранённая публикация с четырьмя цитатами и результаты закрытого раунда. [Протокол CI, HTTPS и браузера](scripts/deploy/pages-live-validation.json) фиксирует проверенный commit и фактические результаты. Прежний сбой источника Pages устранён; его история сохранена в облачном отчёте.

Рабочий адрес публикации: https://arseniy24rus.github.io/demography-lab/. Отдельная форма опроса: https://demography-lab-survey.sunnydew4.chatgpt.site/survey.html. Форма открывает конкретную анкету только по действующему приглашению преподавателя. GitHub Actions Pages собирает `dist` и публикует исполняемое приложение; исходный TypeScript непосредственно не обслуживается.

Онлайн-конфигурация связана с Supabase-проектом `alyrowehwzypgtrqnvdi`. Все миграции через этап 8 применены; проверены 226 прикладных функций, сохранённый импорт и реальный HTTP-сценарий входа, публикации, семейства, голосования и возвращения к результату. Точный протокол размещения и границы проверки приведены в [cloud-deployment.md](docs/cloud-deployment.md). Для автономного семинара эти облачные настройки не требуются.

Исходный проект размещается в [Arseniy24RUS/demography-lab](https://github.com/Arseniy24RUS/demography-lab). В Git сохраняются код, SQL-миграции, тесты, закреплённый корпус, территориальные данные, исходный DOCX-шаблон и локальные шрифты с лицензией. Каталог `dist` создаётся при сборке и не хранится в репозитории; скачанный GitHub Source code ZIP содержит исходники, а накопительный релизный комплект — также собранный клиент.

Для запуска из клона репозитория нужны Node.js 22.12 или новее и npm:

```bash
npm ci
npm run build
node scripts/serve.mjs
```

Для разработки вместо двух последних команд выполните `npm run dev`. Сервер откроется на `http://127.0.0.1:4173/`. Команда `npm ci` использует включённый `package-lock.json`; бинарные шрифты и DOCX-шаблон не требуют Git LFS.

Workflow `.github/workflows/check.yml` проверяет сборку, доменные и клиентские тесты, неизменяемые наборы источников, отделение анонимной анкеты, SQL-миграции, права доступа, контракты SDK/HTTP и автономный сервер. Проверки выполняются без подключения к рабочему Supabase и без отправки писем. Браузерная и эксплуатационная приёмка выбранного размещения выполняется отдельно; workflow не публикует сайт и не применяет миграции к рабочей базе.

Для размещения приложения используется результат `npm run build`: каталог `dist` содержит учебную страницу, отдельную точку входа анкеты, ресурсы, данные и шрифты. Порядок размещения и ограничения двух origin описаны ниже и в [инструкции для анкеты](docs/survey-deployment.md). Адрес хостинга определяется при настройке выбранного контура; ссылка на исходный репозиторий сама по себе не является адресом приложения.

Публичный файл `public/workshop-config.json` допускает только адрес Supabase и publishable/anon key, а также адреса учебного сайта и анкеты. Его можно заполнить перед сборкой либо заменить `workshop-config.json` в размещённом `dist`. Переменные `VITE_*` встраиваются в клиент и имеют приоритет для обычной онлайн-конфигурации. Явная локальная конфигурация сервера 0.7 проверяется первой и всегда сохраняет локальную базу отдельным источником полномочий; ошибочная локальная конфигурация не переключает приложение в облако. Пароль PostgreSQL, `service_role`, ключи `sb_secret_…`, SMTP-пароли и пользовательские токены хранятся вне Git и клиентской сборки. `.env.example` содержит только пустой образец; `.env` и его локальные варианты исключены из Git.

## Запуск статического просмотра готового комплекта

Этот раздел описывает сервер просмотра источников и локальной тетради. Для многопользовательского семинара без интернета используйте `macos/Start-Seminar.command` или `scripts/offline/server.mjs` по инструкции выше.

Нужен установленный **Node.js 22.12 или новее**. Распакуйте комплект целиком, откройте терминал в его корневом каталоге и выполните:

```bash
node scripts/serve.mjs
```

Откройте **http://127.0.0.1:4173/**. Установка npm-пакетов для готовой сборки не нужна: сервер использует только стандартную библиотеку Node.js, а браузер получает уже собранные файлы из `dist`. Для остановки сервера нажмите `Ctrl+C`.

Файл `dist/index.html` следует открывать через этот HTTP-сервер. Двойной щелчок по HTML и режим `file://` не обеспечивают корректную загрузку данных и Web Worker.

Другой порт задаётся переменной `PORT`. Например, в Bash:

```bash
PORT=4174 node scripts/serve.mjs
```

В PowerShell:

```powershell
$env:PORT = "4174"
node scripts/serve.mjs
```

Сервер всегда слушает `127.0.0.1`. Адрес, схема и порт определяют пространство локального хранения: `127.0.0.1:4173`, `localhost:4173` и `127.0.0.1:4174` открывают разные локальные тетради. Для возврата к работе используйте тот же адрес и тот же профиль браузера.

## Новый модуль барьеров и решений

В совместной сессии откройте «Барьеры и решения». Путь родительства содержит восемь этапов и допускает несколько применимостей одной карточки. Участники обсуждают барьеры, связывают их с семействами практик и объясняют механизм. Основания связи закрепляются целиком: изменение публикации или группировки требует повторной проверки, сохраняя прежние цитаты. Авторское предложение содержит адресата, первый шаг, ресурсы и проверяемый показатель. Проектор дополнен барьерами, связями и решениями.

Анкета имеет отдельную точку входа `survey.html` и должна размещаться на самостоятельном origin. Личный ответ не связывается с учебным профилем; есть независимый ключ отзыва, раздельные согласия на исследование и цитирование. Исследовательский ZIP сохраняет JSON, защищённый CSV, вопросы и описание процедуры. Физический проект БД остаётся общим, поэтому абсолютная анонимность не заявляется. Без настройки отдельного адреса сбор личных ответов отключён.

| Паспорта региональных программ | 89 записей, включая явные сведения об отсутствующих источниках |

Полнота исходного документа и качество извлечения учитываются отдельно. Три частичных источника относятся к Вологодской области, Марий Эл и Челябинской области. У Московской области страницы 57 и 70 не дали текстового слоя; извлечение отмечено как требующее проверки. Четыре региональные записи имеют статус недоступного источника, ещё пять — отсутствующего. Состав 89 паспортов описывает переданный набор данных и не означает, что собраны все действующие редакции программ.

Корпус и каталог происходят из [family-support на зафиксированном коммите](https://github.com/Arseniy24RUS/family-support/tree/5dde46ae663b7652a448ec982585e64d61a26a61). Для каждого документа сохранены редакция, SHA-256 и ссылка на оригинал. Подробности доступны в [каталоге данных](docs/data-catalog.md) и [манифесте переиспользования](reuse-manifest.json).

Полный автономный Mac-комплект содержит 80 исходных региональных PDF с проверенными SHA-256, суммарно 379 536 834 байта. В локальном режиме ссылки читателя открывают эти файлы на Mac, включая переход к нужной странице и HTTP Range для больших PDF. Канонический текст, редакции и контрольные суммы источников сохраняются. Внешние сайты и их текущие редакции не становятся локальными: для перехода на официальный сайт потребуется интернет. В Git оригиналы не дублируются; `node scripts/cache-originals.mjs` загружает закреплённые файлы при подготовке, `--check` проверяет уже включённые копии без сетевых запросов.

## Рабочий цикл

| Шаг | Действие и результат |
| --- | --- |
| Открыть источник | Выберите программу в библиотеке. Паспорт показывает происхождение и редакцию; читатель открывает файловые страницы. |
| Найти основание | Используйте поиск, переход к странице и выделение текста. Доступен выбор целых блоков, позволяющий работать без точного выделения пальцем. |
| Сохранить находку | Сохраните цитату с примечанием либо перейдите к сопоставлению с практикой. Якорь хранит точный текст, границы фрагментов и идентификатор редакции. |
| Проверить поля | Для механизма, получателей, размера и условий отдельно укажите, подтверждает ли их цитата, подтверждает частично или выявляет противоречие. |
| Сравнить варианты | Откройте подготовленные карточки. Кнопка «Загрузить полный каталог мер» подключает весь исходный справочник; суммы и условия разных объектов сохраняются отдельно. |
| Создать решение | Добавьте авторскую карточку для выбранного региона и заполните установленные сведения. Документальные основания её полей проверяются отдельно. |
| Продолжить на другом устройстве | Откройте ту же платформу и введите свой email. Цитаты, авторские карточки и проверки загрузятся из профиля. Готовая дорожная карта скачивается в DOCX или PDF в разделе «Проверка и экспорт». |

| Обсудить основания | Общая доска показывает карточку, точные цитаты, источники и авторство. Кнопка открытия источника возвращает к исходному фрагменту. Преподаватель выбирает работу для проектора. |
| Распределить программы | Карта и поиск показывают состояние каждого региона. Участник берёт программу на 30 минут, продлевает назначение и отмечает завершение с публикацией либо пояснением. |
| Объединить практики | Преподаватель сравнивает региональные варианты, подтверждает группировку и сохраняет общий механизм. Суммы, получатели, условия и источники остаются у каждого варианта. Перетаскивание дублируется кнопками. |

| Представить коллективный результат | Проектор переключается между карточкой, картой охвата и рейтингом. Фиксация показа удерживает композицию на время устного обсуждения. |

В новой тетради приложение загружает манифест, подготовленные практики и выбранный документ. Полный каталог подгружается отдельно. При восстановлении сохранённых связей с его карточками интерфейс может запросить этот каталог для открытия ранее выполненной работы.

Подтверждённая цитата означает, что определённый фрагмент поддерживает определённое поле карточки. Эта отметка не устанавливает актуальность правовой нормы на дату занятия и не доказывает влияние меры на рождаемость. Предложение из программы, действующая по описанию источника мера и рекомендация работодателю сохраняют своё исходное различие.

## Локальное хранение и перенос работы

Сохранённые цитаты, авторские карточки, решения по связям и состояние чтения вошедшего участника находятся в его личной серверной тетради. Онлайн это Supabase, в автономном режиме — постоянная база на Mac преподавателя. Имя хранится отдельно в профиле; его изменение через шапку не меняет email, UUID или авторство работ. Совместные публикации и дорожные карты сохраняются прежними доменными командами.

Сохранение подтверждается только после серверной транзакции. При конфликте загружается новая редакция, а введённый текст остаётся в форме для сравнения и повторного сохранения. При сбое связи успешное сохранение не объявляется. Повторный запрос использует идентификатор операции; неизменившаяся тетрадь проверяется компактной ревизией без повторной загрузки полного содержимого. Личные тетради разных профилей не показываются друг другу.

Гостевые заметки и тетради прежних версий остаются в браузере. После входа раздел «Моя работа» предложит «Добавить прежние заметки», если найдёт не перенесённые записи. Перенос требует явного действия: платформа не приписывает прежнюю работу новому пользователю автоматически. Исходная локальная копия не удаляется; импортированные проверки отмечаются для повторного сопоставления.

В обычном интерфейсе нет сохранения ZIP/JSON, импорта архивов или отдельного локального профиля. Дорожные карты скачиваются в DOCX и PDF из зафиксированной версии. Внутренние снимки, серверные резервные копии и независимая исследовательская выгрузка остаются техническими механизмами, не заменяющими сохранение учебной работы.

## Смартфоны и размещение для занятия

`127.0.0.1` доступен только на том устройстве, где работает сервер. На телефоне этот адрес указывает на сам телефон. Для онлайн-занятия используется опубликованный HTTPS-сайт. Для автономного занятия участники открывают LAN-адрес Mac из окна «Подключение к мастерской»; основной HTTP-порт 8787, независимая анкета — 8788. Проверки хешей и безопасный генератор идентификаторов работают и на локальном HTTP.

В корне учебной сборки должны находиться `index.html`, `assets`, значок, `data` и `fonts`. Публичная анкета `survey.html` размещается отдельно по [инструкции](docs/survey-deployment.md). Обычная команда `npm run build` уже копирует `public/data` в `dist/data`. Если готовый архив поставляется без дубликата `dist/data`, перед публикацией скопируйте `public/data` в каталог `data` рядом с опубликованным `index.html`. Локальный сервер умеет делать этот fallback самостоятельно; обычный статический хостинг о расположении `public/data` не знает.

Для совместной работы разместите рядом с `index.html` файл `workshop-config.json` с HTTPS-адресом проекта и публичным publishable key. Образец находится в `public/workshop-config.json`; `npm run build` копирует его в `dist`. При запуске готового комплекта локальный сервер читает файл из `public` и разрешает подключения CSP только к указанному origin и его WebSocket-адресу. Перезапустите сервер после изменения настроек. Ключ `service_role`, `sb_secret_…` и строка подключения PostgreSQL в браузер не передаются.

После подключения Supabase участники с разных устройств получают одну доску занятия. Простой вход использует автоматическую серверную сессию и сверяет компактные курсоры каждые две секунды; полные материалы загружаются при изменении. Локальный режим использует тот же интервал. Прежний Auth-транспорт сохраняет совместимость с Realtime для исторических интеграций. Интерфейс различает живое соединение, сверку и сетевую ошибку. Успешная отправка показывается после ответа сервера. Голоса используют отдельный курсор, поэтому не заставляют скачивать доску публикаций. Неизменяемые материалы раунда кешируются; последующие компактные ответы передают состояние и оценки. Это уменьшает повторную передачу данных, но не является гарантией нулевой стоимости размещения.

## Методические ограничения оценивания

Рейтинг отражает суждение участников конкретного занятия о приоритете адаптации практики. Он не устанавливает доказанный эффект меры на рождаемость. Ответ «не могу оценить» учитывается в охвате, но исключается из знаменателя доли поддержки. Отсутствие ответа хранится отдельно. Материалы, вопрос, участники и пороги фиксируются до голосования; новый состав или вопрос требуют нового раунда. Краткое руководство находится в [runbook-stage-03.md](docs/runbook-stage-03.md), технические решения — в [architecture-stage-03.md](docs/architecture-stage-03.md).
