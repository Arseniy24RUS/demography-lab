# Общий флипчарт

Это открытые для текущего занятия тезисы, а не исследовательская анкета. После обычного входа участник может добавить несколько коротких барьеров (`barrier`) и условий (`condition`). Рядом с ними не отображается автор. Исторические `research.responses`, их согласия, отдельный транспорт и срок хранения остаются самостоятельным модулем: миграция не читает, не переносит, не публикует и не удаляет эти ответы.

## Текст и видимость

Текст нормализуется в NFC, последовательности пробельных символов заменяются одним пробелом, концевые пробелы удаляются. Длина после нормализации — от 1 до 180 кодовых точек Unicode, включая emoji; управляющие непробельные символы запрещены. HTML и Markdown не интерпретируются. Текст опубликованного тезиса неизменяем: исправление требует снять старый и добавить новый. Совпадение текста не объединяет тезисы автоматически. Ограничения «один ответ на человека» нет; общий технический предел занятия — 20 000 записей, включая снятые.

Открытый DTO содержит только `id`, `kind`, `text`, `status`, `createdAt`, `revision`, `support`, `oppose`, `score`. Обычному участнику дополнительно возвращаются только его собственные `myVote`, `myVoteRevision`, `canWithdraw`. DTO проектора исключает эти три поля полностью и проверяется отдельной строгой схемой. UUID автора, email, ФИО, списки голосовавших и индивидуальные голоса других участников не выдаются. Сервер приватно хранит автора для снятия/возврата тезиса и участника голоса для защиты от повторного учёта. Это анонимность отображения, а не необратимое обезличивание базы.

## Голоса и снятие

Один участник имеет один текущий голос на тезис: `1`, `-1` или `null` (голос снят). Нулевой голос не предусмотрен. Собственный тезис можно оценить; автоматического голоса при публикации нет. `score = support - oppose`. Голосование не устанавливает эффективность демографического воздействия, но выражает отношение присутствующих к тезису. `revision` тезиса меняется только при его снятии/возврате. `myVoteRevision` начинается с 0 и увеличивается при изменении собственного голоса, в том числе при снятии; повтор текущего значения с актуальной ревизией ничего не меняет.

Снять и вернуть тезис могут автор и преподаватель. Снятый тезис исключается из всех досок, но остаётся в базе для отмены действия и проверки повторных команд. Голоса сохраняются при возврате того же неизменённого текста. Во время снятия новые голоса отклоняются. Повтор старой команды не восстанавливает снятую запись и не возвращает устаревший результат.

## RPC

`dw_flipchart_updates(p_session_id, p_after_cursor = null, p_projector = false)` возвращает `{sessionId,cursor,reset,notes,removedIds}`. `notes` содержит только активные записи. При `null` или курсоре больше текущего возвращается полный снимок с `reset:true`, активными тезисами и пустыми `removedIds`. Неотрицательный курсор, совпадающий с текущим, возвращает пустую дельту. Отрицательный курсор запрещён. В обычной дельте `notes` содержит актуальные состояния всех изменившихся активных записей, `removedIds` — изменившиеся снятые записи. Несколько изменений одной записи сворачиваются в её последнее состояние. Курсор и записи читаются из одного согласованного SQL-снимка.

`dw_flipchart_add(p_operation_id,p_session_id,p_input)` принимает `{kind,text}`. `dw_flipchart_vote(p_operation_id,p_session_id,p_note_id,p_expected_revision,p_input)` принимает `{value}`; ожидаемая ревизия — `myVoteRevision`. `dw_flipchart_status(p_operation_id,p_session_id,p_note_id,p_expected_revision,p_input)` принимает `{status}`; ожидаемая ревизия — `revision` тезиса. Все три возвращают `{sessionId,cursor,note}`. `note` включает снятую запись при соответствующем действии, позволяя предложить её немедленный возврат.

Клиент не продвигает курсор чтения по ответу мутации: он применяет конкретную запись, затем получает дельту от последнего прочитанного курсора. Иначе промежуточное добавление другого участника может быть пропущено. Старый ответ после смены аккаунта/занятия не применяется. Повтор при транспортной ошибке использует тот же operation ID и тот же payload; смена содержания при том же ID отклоняется как `IDEMPOTENCY_CONFLICT`. Конфликт ревизии не переписывает голос молча.

## Хранение и права

Таблицы `private.dw_flipchart_state`, `private.dw_flipchart_notes`, `private.dw_flipchart_votes` закрыты от прямого доступа `anon` и `authenticated`, с включённым RLS без публичных политик. Изменения курсора, тезиса, агрегатов и квитанции атомарны. Блокировка строки состояния сериализует изменения одного флипчарта, отдельные тезисы не могут получить одинаковый курсор. RPC доступны только действующим участникам или преподавателю текущей общей мастерской. Доступ проверяется и при повторе квитанции. Обычный участник может читать проекцию. Отдельного разрешения преподавателя, приглашения и открытия флипчарта не требуется.

Облачный PostgREST использует существующий `dw_entry_rpc`; локальный сервер исполняет те же функции в постоянной PGlite-базе. Новые RPC не входят в независимый анонимный origin исторической анкеты. Данные, ревизии, курсор и квитанции сохраняются при перезапуске локального сервера; браузерное хранилище не является общей базой.
