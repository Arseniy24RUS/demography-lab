# Расчётное ядро дорожных карт

Версия алгоритма `roadmap-analytics-1`. Пакет содержит чистые функции TypeScript; сетевые обращения, авторизация и запись источников находятся за его пределами. Импортировать публичный API следует из `packages/analytics/index.ts`. Канонические определения и статистические ряды переиспользуются из `packages/territories`; снимки дорожной карты — из `packages/roadmaps`.

## Доступные операции

| Функция                                                         | Назначение                                                                                                   |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `computeCanonicalScenario(series, parameters)`                  | Расчёт по тому же закреплённому ряду, который возвращает SQL и хранит зафиксированная версия                 |
| `computeScenario(input)`                                        | Общая числовая модель для муниципальных и явно определённых операционных показателей                         |
| `pointsFromStatisticsPack(pack, territoryKey, metricId)`        | Точное извлечение колонки из регионального пакета; неоднозначность не разрешается случайным выбором          |
| `suggestHistoryWindow(points, maxYears)`                        | Последний непрерывный интервал с доступными значениями; поздний null не становится базовым годом             |
| `calculateCostKopecks(input)`                                   | Стоимость одной строки с точными целыми операндами и округлением до копейки                                  |

## История и происхождение данных

Встроенные ряды используют количественные компоненты пользовательского `Settlements-projection-dashboard`. Неполная первичная документация фиксируется как `provenanceStatus=incomplete_primary`, а непроверенная сопоставимость границ — как `geographyComparability=not_verified`. В расчёте и экспорте сохраняются предупреждения. Числа из авторского набора не становятся автоматически текущей официальной выгрузкой БДМО.

Среднегодовая численность `pop_mid` имеет reference `annual_average`; она не переименовывается в численность на 1 января. Показатель относится к stock для запрета суммирования разниц по годам под названием дополнительных жителей. Рождения, смерти и миграционные потоки имеют reference `calendar_year`; миграционное сальдо и естественный прирост допускают отрицательные значения. Производный естественный прирост вычисляется импортёром только при наличии обеих компонент.

Год и значение определяют точку. `null` обозначает отсутствие и сохраняется в истории; число `0` остаётся наблюдаемым нулём. Повторный год и нечисловое значение вызывают ошибку. Отсутствующие годы внутри выбранного окна представлены явными пропусками, которые нельзя соединять непрерывной линией наблюдений. Заполнение пропуска нулём, интерполяция и территориальная гармонизация в этом ядре не выполняются.

Точка старта определяется по последнему доступному значению конкретного показателя. Выбранный конечный год истории и фактический базовый год выводятся раздельно. `trainingYears` содержит годы, которые действительно использовал метод; параметры выбора окна сохранены независимо.

## Базовая траектория

`last_value` сохраняет последнее доступное значение. Метод работает с одной точкой, сопровождая короткую историю предупреждением. Называть такую траекторию причинным сценарием отсутствия мероприятий нельзя.

`linear` оценивает обычный линейный тренд по реальным номерам лет. Требуются минимум пять последовательных доступных лет внутри используемого ряда. Пропуски до первого или после последнего доступного года сохраняются и сопровождаются пояснением; внутренний разрыв запрещает линейную экстраполяцию. Интерфейс может предложить последний непрерывный отрезок через `suggestHistoryWindow`.

Расчёт использует центрированные значения времени: `x=year−firstYear`, `b=Σ(x−meanX)(y−meanY)/Σ(x−meanX)²`, `a=meanY−b×meanX`. Последующее значение равно `a+b×x`. Прогнозные значения ограничиваются допустимой областью показателя; каждый такой случай имеет флаг `baselineClipped` и предупреждение. Исходные значения не изменяются.

При восьми и более точках выполняется простая проверка двух последних лет: тренд обучается только на предшествующих значениях, после чего сравнивается MAE с сохранением последнего уровня. Два отложенных года не участвуют в оценке тестового тренда. Результат является локальной диагностикой ряда и не подтверждает внешнюю прогностическую точность.

Допускается горизонт от одного до тридцати лет после последней доступной точки; горизонт свыше десяти лет сопровождается предупреждением. Вероятностные интервалы не рассчитываются. Траектории withMIG/noMIG из исходного репозитория не подмешиваются в простую базу без самостоятельной проверки их шкалы и предпосылок.

## Целевые траектории

В параметре `targetValue` число `10` означает десять процентов или десять процентных пунктов, когда применим соответствующий режим. Обозначим последнюю доступную точку `y0,t0`, горизонт `H`, базу `B(t)` и долю времени `h=(t−t0)/H`.

| Режим                | Расчёт                                                               |
| -------------------- | -------------------------------------------------------------------- |
| `absolute_end`       | `y0+(targetValue−y0)×h`                                              |
| `relative_end`       | `B(t)×[1+(targetValue/100)×h]`                                       |
| `annual_growth`      | `y0×(1+targetValue/100)^(t−t0)`                                      |
| `absolute_delta_end` | `B(t)+targetValue×h`                                                 |
| `percentage_points`  | `B(t)+targetValue×h`, только для явно заданной шкалы percent [0,100] |

Относительные режимы запрещены при неположительной базе и знакопеременной семантике показателя. Для миграционного сальдо −80 абсолютный прирост 8 даёт −72. Изменение ниже −100% недопустимо. Конечная цель вне допустимого диапазона отклоняется; промежуточное ограничение модели отражается явно.

При базе конечного года 80 увеличение на 10% к концу даёт 88. Ежегодное увеличение стартового уровня 80 на 10% в течение четырёх лет даёт 117,128. При старте 100 тот же ежегодный темп даёт 146,41. Контрольные примеры проверены автоматически.

Расчётная цель и округлённый план для целочисленных показателей хранятся раздельно как `targetValue` и `plannedTargetValue`. Суммировать годовые разницы разрешается только для flow. Для stock, rate и share `cumulativeFlowGap=null`; доступна разница конечной даты. Разность подписывается как плановый разрыв, не как эффект мероприятия.

СКР не выводится из общей численности или общего коэффициента рождаемости. Официальное определение связывает СКР с возрастными коэффициентами рождаемости; требуются соответствующие возрастные данные. Первичные ориентиры: [методологические пояснения Росстата](https://www.rosstat.gov.ru/storage/mediabank/mdemo2.htm) и [приказ Росстата №542 от 30.09.2025](https://rosstat.gov.ru/storage/mediabank/met_542-30092025.pdf). Включённые семь муниципальных рядов не предоставляют входов для самостоятельного расчёта СКР; соответствующей формулы в ядре нет.

## Деньги, ресурсы и финансирование

Денежные операнды хранятся целыми копейками в безопасном диапазоне JavaScript. Количество хранится десятичной строкой до трёх знаков и преобразуется в тысячные доли через BigInt. Итог строки: `round_half_up(quantityMilli×unitPriceKopecks×periods/1000)`. Все промежуточные денежные операции выполняются целыми числами; итоговые суммы проверяются на переполнение. Округление производится один раз на завершённой расходной строке, после чего строки суммируются в копейках.

Распределение ссылается на действующую расходную строку. Дубли идентификаторов и чужие/отсутствующие строки отклоняются. Сумма подтверждённых и ожидаемых распределений не может превышать стоимость строки. Неденежный вклад имеет отдельную оценку и не получает кассовые распределения.

Подтверждённые цены и финансирование требуют источника и календарной даты. Статусы `budget_draft`, `application` и `assumption` относятся к ожидаемому финансированию. Смета раскрывает `needCashKopecks`, `inKindKopecks`, `confirmedKopecks`, `expectedKopecks`, `confirmedGapKopecks` и `remainingAfterExpectedKopecks`. Происхождение трансферта описывается отдельно и не добавляется к расходу повторно.

Контрольный пример: 40 семей × 6 часов × 500 рублей × 6 месяцев = 720 000 рублей. Подтверждённые 500 000 рублей оставляют разрыв 220 000 рублей. Заявка на грант 220 000 рублей не уменьшает разрыв подтверждённого финансирования. Числа являются учебным примером, не нормативом стоимости услуги.

Стоимость на семью использует известное положительное целое число уникальных семей; при неизвестном или нулевом знаменателе результат отсутствует. Стоимость дополнительного рождения не рассчитывается. Проверка суммы и наличия источника не является юридическим заключением о расходном обязательстве.

## Календарь и комплектность

Календарь использует дни UTC и строгие даты `YYYY-MM-DD`. Продолжительность включительна: действие с одинаковой датой начала и окончания длится один календарный день. Региональные праздники и рабочие дни не подменяются предположениями браузера. Finish-to-start означает начало не раньше дня после окончания предшественника плюс `lagDays`.

Циклы, некорректные даты, дубли и чужие зависимости выявляются. Отсутствующие даты остаются черновиком. Выход за период проекта, нарушение последовательности и несовпадение бюджетного года показываются как вопросы согласования; массовый перенос чужих действий самопроизвольно не производится.

Комплектность — число завершённых явных критериев из 31. Разделы: паспорт, исходная ситуация, показатели, мероприятия, календарь, ресурсы, риски, мониторинг. Пустой документ имеет 0%; нулевое исходное значение считается заполненным. Даже при 100% сохраняются предупреждения о непроверенном внешнем факте, плановой цене или происхождении ряда. Научное качество, доказанность эффекта и правовая допустимость такой шкалой не измеряются.

При пересчёте зафиксированной дорожной карты идентификатор и fingerprint статистического ряда должны совпадать с сохранёнными параметрами сценария. Несовпадение даёт явную ошибку, не подменяется текущей доступной редакцией. Самостоятельные анкеты и личные ключи в расчётные входы не входят.

## Проверки

`npx vitest run packages/analytics` проверяет формулы, границы доменов, историю с пропусками, реальные нули, signed-значения, отсутствие утечки отложенных лет в обучение, процентные пункты, точные копейки, бюджетный разрыв, циклы и календарные дни, комплектность шаблона и совпадение закреплённых источников.

Проверки не устанавливают демографическую эффективность мероприятий, актуальность первичных данных, действие законодательства или производительность размещённой базы. Подключение нового источника требует самостоятельного документирования и проверки; изменение математического правила — новой версии алгоритма.
